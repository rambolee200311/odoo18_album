## 1. 实施总览

### 1.1 实施顺序

```text
CC-01 核心数据模型与后台
        │
        ├── TDD-Q-008 动态来源运行时验证
        ▼
CC-02 媒体采集
        ▼
CC-03 审核与发布
        ▼
CC-04 Portal 查看器
        ▼
CC-07 批量 ZIP 下载
```

### 1.2 全局实施原则

- 以冻结的 SRS 和 TDD 为唯一实施基线；
- 每个 CC 只实现其明确范围，不提前扩大到后续 CC；
- 业务规则放在 ORM/业务动作中，不能只依赖 UI；
- 所有附件引用不复制原始 `ir.attachment`；
- 所有 Portal 媒体读取遵守“授权先于 `sudo()`”；
- 所有动态来源必须通过 Source Config 允许列表；
- 完成一个 CC 后，必须形成该 CC 的代码、验证证据和关闭材料，再进入下一个 CC；
- 发现 SRS/TDD 语义缺口时暂停相关实现，回到上游文档确认。

### 1.3 跨 CC 依赖

| 依赖 | 解决节点 | 门禁类型 |
|---|---|---|
| 模型、权限和后台基础 | CC-01 | 硬门禁 |
| 动态来源 Registry/`record[field_name]` 可行性 | CC-01 结束前、CC-02 开始前 | 硬门禁（阻塞 CC-02 来源采集） |
| 媒体采集和 Item 完整性 | CC-02 | 硬门禁 |
| 发布状态和 Portal 可访问的 Album | CC-03 | 硬门禁 |
| 媒体 Controller 和查看器 | CC-04 | 硬门禁 |
| ZIP 资源配置 | CC-07 开始前 | 硬门禁 |

## 2. CC-01 — 核心数据模型与后台

### 2.1 目标

建立四个 ORM 模型、关系、约束、基础权限和后台管理界面，使用户可以独立创建和整理相册、相页及空的相册项结构。

### 2.2 输入

- SRS §4、§7.1、§7.5、§7.6、§9、§10；
- TDD §2、§10、§11；
- TDD-Q-001 至 TDD-Q-003 当前状态；
- Odoo 18 Community Edition 基础模块和项目 Python 环境。

### 2.3 任务拆分

#### CC-01-T01 模块骨架和依赖

- **输入**：TDD §1、项目模块名和依赖列表；
- **工作范围**：建立模块清单、Python 包结构、数据文件入口、视图和安全文件入口；
- **输出**：可被 Odoo 识别的模块骨架和依赖声明；
- **依赖**：无；
- **完成条件**：模块清单与 SRS 依赖一致，不引入具体来源业务模块。验证方式是检查模块 `__manifest__.py` 的 `depends` 列表不包含任何具体业务模块；CI 增加对应的依赖清单检查规则。

#### CC-01-T02 Album ORM 模型

- **输入**：TDD §2.2、§5、§6；
- **工作范围**：实现名称、客户、描述、状态、Token、有效期、审核/发布时间和相页关系；
- **输出**：`wd.evidence.album` 模型和状态动作接口边界；
- **依赖**：CC-01-T01；
- **完成条件**：客户写入规范化为 Commercial Partner；状态不能通过普通写入任意跳转；Token 字段具备唯一性设计。

#### CC-01-T03 Page ORM 模型

- **输入**：TDD §2.3、§4、§10；
- **工作范围**：实现 Page 与 Album 的关系、标题、描述、顺序和 Item 关系；
- **输出**：`wd.evidence.album.page` 模型；
- **依赖**：CC-01-T02；
- **完成条件**：Page 只能属于一个 Album；跨 Album 移动被拒绝；删除 Page 不删除附件。

#### CC-01-T04 Item ORM 模型和关系完整性

- **输入**：TDD §2.4、SRS §15.2、§15.5；
- **工作范围**：实现 Item 字段、来源快照、媒体类型、可用性、顺序和附件引用；
- **输出**：`wd.evidence.album.item` 模型；
- **依赖**：CC-01-T03；
- **完成条件**：
  - `attachment_id` 删除后 Item 保留；
  - `album_id` 由 `page_id.album_id` 派生且不可独立编辑；
  - `page_id.album_id == album_id` 不一致时拒绝；
  - `availability_state` 在附件创建、修改、删除关联和读取前统一刷新；
  - 可用性刷新逻辑集中在 Item 模型，不散落在视图或 Controller；
  - 同一 Album 的附件唯一性有数据库和业务双重保护；
  - 删除 Item 不删除附件。

#### CC-01-T05 Source Config ORM 模型

- **输入**：TDD §2.5、§3；
- **工作范围**：实现来源模型、字段名、标签、标题/描述字段和启用状态；
- **输出**：`wd.evidence.album.source.config` 模型和配置约束入口；
- **依赖**：CC-01-T01；
- **完成条件**：配置唯一性、启停策略和字段校验接口明确；不自动启用候选字段；字段校验接口必须与 CC-02-T01 的 Resolver 调用方式一致，避免 CC-02 时重新设计校验入口。

#### CC-01-T06 基础 ACL 和 Record Rule

- **输入**：SRS §9、TDD §11；
- **工作范围**：建立业务用户、审核人、管理员的模型访问和相册归属规则；
- **输出**：模块 ACL、Record Rule 和组定义；
- **依赖**：CC-01-T02 至 CC-01-T05；
- **完成条件**：普通用户只能管理自己的 Album；审核人和管理员权限与 SRS 矩阵一致；Portal 不通过后台 ACL 获得媒体权限。

#### CC-01-T07 后台视图和排序

- **输入**：TDD §10、SRS §7.1、§7.5、§7.6；
- **工作范围**：Album 表单、Page 管理、Item 管理、基础列表/搜索和顺序编辑；
- **输出**：后台 XML 视图、菜单、动作和排序交互；
- **依赖**：CC-01-T02 至 CC-01-T06；
- **完成条件**：能够创建 Album/Page、调整同 Album 内 Page 顺序、调整同 Page 内 Item 顺序；不能通过 UI 跨 Album 移动 Page。

#### CC-01-T08 CC-01 关闭材料

- **输入**：CC-01 所有任务输出；
- **工作范围**：整理实施记录、自动化验证记录、人工验证证据和遗留问题；
- **输出**：CC-01 对应的 IHR/ATR/HVR 输入和 FR 草稿；
- **依赖**：CC-01-T01 至 CC-01-T07；
- **完成条件**：CC-01 验收条件全部有证据，未解决问题明确标记并禁止假设通过；关闭材料遵循 §8 的最低内容要求。

### 2.4 CC-01 验收条件

1. 模块可安装，且不依赖具体来源业务模块；
2. 四个模型和关系与 TDD §2 一致；
3. Album/Page/Item 的删除策略不删除原始附件；
4. `album_id` 派生和一致性约束有效；
5. 同一附件在同一 Album 不能重复；
6. 页面排序和 Item 排序只能在所属边界内调整；
7. 后台角色权限符合 SRS §9；
8. Source Config 可以维护但不会自动暴露所有候选字段；
9. CC-01 关闭材料形成。

### 2.5 CC-01 依赖的待确认项

- **TDD-Q-001**：空相册发布策略可以延后到 CC-03，但必须在 CC-03 发布动作开发前解决；
- **TDD-Q-002**：标题/描述默认映射可以延后到 CC-02，但必须在从记录创建 Page 前解决；
- **TDD-Q-003**：来源信息展示配置可以延后到 CC-04，但必须在 Portal 数据展示前解决；
- **TDD-Q-008**：必须在 CC-01 结束前完成或明确验证方案，CC-02 开始前不得保持未知状态。

## 3. CC-02 — 媒体采集

### 3.1 目标

实现从已配置来源记录选择媒体、从记录创建 Page、直接上传媒体和 Item 完整性校验。

### 3.2 输入

- SRS §5、§6、§7.2—§7.6、§15.3—§15.5；
- TDD §3、§4；
- CC-01 的模型、约束和后台结构；
- **TDD-Q-008 的验证结果**；
- TDD-Q-002 的已确认字段映射规则。

### 3.3 任务拆分

#### CC-02-T01 动态来源 Resolver

- **输入**：TDD §3、已解决的 TDD-Q-008；
- **工作范围**：读取 Source Config、重新校验模型/字段/relation/权限，并返回动态附件 Recordset；
- **输出**：来源解析业务入口；
- **依赖**：CC-01-T05、TDD-Q-008；
- **完成条件**：不硬编码模型名或字段名；来源记录读取使用普通权限；无效配置产生明确错误。

#### CC-02-T02 标题和描述映射

- **输入**：SRS §6.2、§6.3、TDD §4.2、TDD-Q-002；
- **工作范围**：读取配置的标题/描述字段，应用已确认的默认推导规则；
- **输出**：从记录创建 Page 的初始标题和描述；
- **依赖**：CC-02-T01；
- **完成条件**：用户可以覆盖自动填充的值；Page 创建后不保留持续来源绑定。

#### CC-02-T03 来源附件合法性校验

- **输入**：SRS §15.3、TDD §2.4、§4.3；
- **工作范围**：检查附件存在、非空、MIME/扩展名合法、媒体类型可识别、来源记录权限和同 Album 唯一性；
- **输出**：统一媒体校验入口；
- **依赖**：CC-01-T04、CC-02-T01；
- **完成条件**：只接受 JPG/JPEG/PNG/MP4；MIME 与扩展名必须一致；内容可读性校验失败时拒绝，不根据扩展名猜测；拒绝其他类型和无权限来源。

#### CC-02-T04 从记录创建 Page

- **输入**：来源 Resolver、标题/描述映射、附件合法性校验；
- **工作范围**：创建 Page 和 Item，保存来源模型、记录 ID、字段名追溯快照；
- **输出**：可编辑的 Page 和媒体 Item；
- **依赖**：CC-02-T01 至 CC-02-T03；
- **完成条件**：新增来源附件不会自动同步；Page 与来源记录不持续绑定。

#### CC-02-T05 从记录向既有 Page 添加媒体

- **输入**：CC-02-T01、CC-02-T03；
- **工作范围**：从已配置来源记录向既有 Page 建立 Item 引用；
- **输出**：来源型 Item；
- **依赖**：CC-02-T04；
- **完成条件**：同一附件在整个 Album 内重复时拒绝；删除 Item 不删除来源附件。

#### CC-02-T06 直接上传

- **输入**：SRS §15.4、TDD §4.4；
- **工作范围**：接收图片/视频上传，创建不绑定业务记录的附件和 Upload 型 Item；
- **输出**：上传型 Item 和附件引用；
- **依赖**：CC-01-T04、CC-02-T03；
- **完成条件**：上传附件不绑定业务单据；事务失败时不留下不可追踪的半成品关系。

#### CC-02-T07 CC-02 关闭材料

- **输入**：CC-02 所有任务输出；
- **输出**：CC-02 IHR/ATR/HVR 输入和 FR 草稿；
- **依赖**：CC-02-T01 至 CC-02-T06；
- **完成条件**：来源采集、直接上传、媒体类型、权限和唯一性均有证据。

### 3.4 CC-02 验收条件

1. 已配置来源字段可以被发现、校验和选择；
2. 具体来源模型和字段不是代码依赖；
3. `record[field_name]` 动态读取在 TDD-Q-008 指定的验证环境中成立；
4. 从记录创建 Page 的标题/描述可覆盖；
5. Page 创建后不持续绑定来源记录；
6. 来源附件和直接上传均可创建 Item；
7. 非法媒体、空附件、无权限来源和重复附件均被拒绝；
8. 删除 Item 不删除附件；
9. 如果 TDD-Q-008 尚未解决，来源采集部分不得进入 CC-02 验收；直接上传部分可以独立完成和验证，关闭材料必须明确区分已验证部分和阻塞部分；
10. CC-02 关闭材料形成。

### 3.5 CC-02 前置门禁

CC-02 开始前必须完成 **TDD-Q-008**。如果真实上游模块尚不可用，必须使用专用测试模型或等效 Odoo Registry 测试替代，并记录替代范围；不得把具体业务模型名称写入生产模块依赖。

## 4. CC-03 — 审核与发布

### 4.1 目标

实现相册状态机、审核动作、发布/撤销、有效期和 Token 生命周期。

### 4.2 输入

- SRS §7.7—§7.10、§10、§15；
- TDD §5、§6、§11；
- CC-01 的状态字段、权限和模型；
- CC-02 的有效 Page/Item 和媒体校验；
- TDD-Q-001 的最终决策。

### 4.3 任务拆分

#### CC-03-T01 状态动作

- **输入**：TDD §5.1、§5.2；
- **工作范围**：实现提交审核、批准、拒绝、发布和撤销动作；
- **输出**：显式状态动作和非法状态拒绝；
- **依赖**：CC-01-T02；
- **完成条件**：禁止跳过审核；拒绝可回到草稿；已发布可撤销。

#### CC-03-T02 审核和发布权限

- **输入**：SRS §9、TDD §11；
- **工作范围**：审核人/管理员动作权限和服务端二次检查；
- **输出**：与按钮无关的后端权限门禁；
- **依赖**：CC-01-T06、CC-03-T01；
- **完成条件**：业务用户不能审核或发布；审核人和管理员权限符合矩阵。

#### CC-03-T03 发布前一致性检查

- **输入**：TDD §5.3、CC-02 媒体校验；
- **工作范围**：发布前再次检查客户、审核人、Page/Item、附件可用性、重复和空相册策略；
- **输出**：发布前统一检查入口；
- **依赖**：CC-02；
- **完成条件**：任何不满足条件的 Album 不得发布。

#### CC-03-T04 Token 和有效期

- **输入**：SRS §7.8—§7.10、TDD §5.4、§5.5；
- **工作范围**：发布生成随机 Token、重置 Token、记录发布时间/撤销时间和有效期判断；
- **输出**：Token 生命周期和访问条件；
- **依赖**：CC-03-T01、CC-03-T03；
- **完成条件**：Token 不提供独立授权；撤销或过期立即影响后续访问判断。

#### CC-03-T05 CC-03 关闭材料

- **输入**：CC-03 所有任务输出；
- **输出**：CC-03 IHR/ATR/HVR 输入和 FR 草稿；
- **依赖**：CC-03-T01 至 CC-03-T04；
- **完成条件**：状态、权限、Token、撤销和有效期均有证据。

### 4.4 CC-03 验收条件

1. 状态只能按 SRS 允许的路径流转；
2. 未审核不能发布；
3. 审核拒绝回到草稿；
4. 发布生成密码学随机 Token；
5. Token 不能绕过登录和 Commercial Partner 授权；
6. 撤销和过期不依赖状态值改变即可阻断访问；
7. 发布前所有媒体和业务约束重新检查；
8. CC-03 关闭材料形成。

### 4.5 CC-03 待确认门禁

- **TDD-Q-001** 必须在 CC-03-T03 开始前解决；
- 如果 TDD-Q-001 未解决，CC-03-T01（状态动作）和 CC-03-T02（审核和发布权限）可以先行，但 CC-03-T03（发布前一致性检查）及其后的发布实现必须等待 TDD-Q-001 解决；
- TDD-Q-002 已应在 CC-02 结束前解决；
- TDD-Q-003 可延后到 CC-04，但不得影响后台审核发布。

## 5. CC-04 — Portal 查看器

### 5.1 目标

实现登录客户的相册列表、查看器、媒体预览、下载和 OWL 交互。

### 5.2 输入

- SRS §8、§11、§12、§13；
- TDD §6、§7、§9、§12；
- TV-01、TV-02、TV-04；
- CC-03 已发布 Album；
- TDD-Q-003、TDD-Q-007 的决策；
- TDD-Q-008 已解决的动态来源事实。

### 5.3 任务拆分

#### CC-04-T01 Portal 访问策略

- **输入**：TDD §6、TV-02；
- **工作范围**：统一实现登录、Portal 组、Commercial Partner、发布、撤销、有效期和对象归属检查；
- **输出**：可被所有 Portal 路由复用的授权入口；
- **依赖**：CC-03；
- **完成条件**：授权检查先于任何附件 `sudo()` 读取。

#### CC-04-T02 Portal 列表和查看器页面

- **输入**：TDD §9、§12；
- **工作范围**：相册分页列表、相册详情、Page 切换和媒体数量展示；
- **输出**：Portal QWeb 页面及受控数据结构；
- **依赖**：CC-04-T01；
- **完成条件**：只显示当前商业实体的已发布、未撤销、未过期 Album。

#### CC-04-T03 媒体 Controller

- **输入**：TV-01、TDD §7、§12；
- **工作范围**：Item ID 媒体路由、单文件下载、MIME、响应头、不可用处理和 Range；
- **输出**：自定义媒体和下载 Controller；
- **依赖**：CC-04-T01、CC-03；
- **完成条件**：不使用 `/web/content`；跨客户和无权限访问返回约定的 404，且 404 不区分“资源不存在”和“资源存在但无权访问”，避免资源存在性泄露；授权后才 `sudo()`。

#### CC-04-T04 OWL 查看器交互

- **输入**：TV-04、TDD §9；
- **工作范围**：PageTabs、媒体筛选、MediaGrid、灯箱、视频播放和选择状态；

## 8. CC 级交付和关闭要求

每个 CC 在进入下一 CC 前必须完成：

1. 代码范围与本计划任务一致；
2. 对应 TDD 条款已落实；
3. 该 CC 的验收条件逐项有验证证据；
4. 未完成项、风险和待确认项已记录；
5. 形成对应 IHR、ATR、HVR 输入；
6. 形成该 CC 的 FR 草稿；
7. 人工评审确认是否允许进入下一个 CC；评审至少包含技术负责人、产品负责人和测试负责人。

### 8.1 关闭材料最低内容

每个 CC 的关闭材料至少包含：

- **IHR（Implementation Handoff Record）**：本次 CC 涉及的接口和数据结构清单；
- **ATR（Automated Test Record）**：本次 CC 的验收测试记录，可引用自动化测试输出；
- **HVR（Human Verification Record）**：本次 CC 的人工验证证据，包括截图、日志和手工步骤记录；
- **FR（Feature Closure Record）草稿**：本次 CC 的功能完成声明和遗留问题清单。

CC 的 FR 只能关闭该 CC，不能替代项目级 PVR/PCR，也不能单独宣布整个项目完成。
